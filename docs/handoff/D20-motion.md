## Timing and easing

These are owner-approved D20-v1 motion specification values, not previously approved D10 tokens. No new variable, component family or animation-style library is created.

| Purpose | Duration | Easing | Limit |
| --- | --- | --- | --- |
| Meaning, focus, selection, pressed/disabled/pending state, language/theme, Reduced Motion | 0 ms | None | Immediate final state; no delay or animation prerequisite |
| Pointer hover color, including return to rest | 100 ms | cubic-bezier(0.2, 0, 0, 1) | Existing semantic colors only; never geometry, text opacity or focus |
| Optional local settled-surface treatment | 120 ms | cubic-bezier(0, 0, 0.2, 1) | Decorative surface treatment only; content stays fully visible |
| Dialog enter | 180 ms | cubic-bezier(0, 0, 0.2, 1) | Translate Y +8 px → 0; full opacity, no scale |
| Navigation drawer / existing side-panel enter | 220 ms | cubic-bezier(0, 0, 0.2, 1) | At most 12 px from its actual edge → 0; no viewport-width sweep |
| Permitted overlay exit | 120 ms | cubic-bezier(0.4, 0, 1, 1) | Reverse the small enter offset, then remove; no semantic/focus delay |

No bounce, spring, parallax, staggered text, pulsing error, automatic scroll flourish, count-up, chart sweep, confetti or decorative looping. No artificial minimum loading time, delayed error display or automatic feedback dismissal. Pixel offsets describe motion only; existing spacing, radii, layout and breakpoints remain authoritative.

## Motion lifecycle and implementation notes

- Meaning and action availability are committed independently of motion. There is no request, success callback, write retry, navigation or focus decision tied to a timeline ending. Pending duration reflects the actual operation, not the 100–220 ms presentation durations. Uncertain outcome releases the pending lock under accepted rules and never automatically replays a write.
- On open, mount final readable content and establish its accepted focus/overlay ownership immediately. Small transforms carry the surface and focus ring together; do not animate the ring independently or clip it. Backdrop/scroll ownership and modal semantics are runtime requirements inherited from accepted overlays, not functioning behavior demonstrated here.
- On permitted close, logical dismissal and focus return happen immediately. If retaining an outgoing surface for its 120 ms visual exit, make it inert/non-focusable and unavailable to assistive reading, without an invisible hit-blocking layer; it cannot retain focus or postpone the next action. Reduced Motion removes it immediately. Dirty/pending guards run before dismissal and remain operation-specific.
- Interrupt/reverse from the currently displayed transform rather than replaying from a distant start. Never queue entrances. If a newer state supersedes a transition, show the new state immediately and cancel obsolete decoration. No cancellation of an issued backend request is implied. Navigation, viewport changes and language/theme switches must not replay entrance or reorder reading through visual animation.
- Future implementation should honor the user's platform Reduced Motion preference without introducing a product setting or persistence claim. A preference change while animating cancels presentation motion and settles immediately at the logically current state, retaining focus and guards. Do not force-enable animation if preference detection is unavailable: the static equivalent is complete.
- Announce meaningful changed state/selected value with the same words under both preferences, without announcing every animation frame, stealing focus on refresh, or relying on color. Keyboard, touch and assistive alternatives remain required. Do not implement smooth scrolling as a prerequisite for reaching content; keep the focused target visible with immediate positioning when needed.
- Use the accepted responsive composition, wrapping and scroll rules. Reserve final layout before a short transform, retain focus-ring clearance, and keep the entire 8/12 px path contained. No layout-size animation, fabricated breakpoint or changed content height to force Arabic into English geometry. Durations do not grow with viewport width.
- These are backend-independent presentation requirements. A future implementation may use a new backend, the audited legacy Supabase reference or another compatible API; actual authorization, transitions, persistence and security must be verified separately. No implementation code or new dependency is part of D20.
